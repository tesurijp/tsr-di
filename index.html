C# SOURCE GENERATOR

依存解決は、 コンパイル時に。

実行時に登録表を探索する DI から、生成コードで直接呼び出す DI へ。 クラスだけでなく、メソッドも型安全なサービスとして解決します。

01 / THE IDEA

依存解決を、実行時に持ち込まない。

実行時に登録表を構築・探索する一般的な DI コンテナに対し、tsr-di は Source Generator がコンパイル時に依存関係を確定します。実行時は生成されたコードがコンストラクターやメソッドを直接呼び出すため、登録表の構築・探索やリフレクションによる依存解決の負荷がありません。未登録や登録の競合も、ビルド時に検出します。

02 / IN PRACTICE

クラスも、メソッドも、解決対象に。

オブジェクトだけでなく、必要な操作そのものを依存関係として宣言できます。

クラスを、生成コードで直接解決

属性で実装とライフタイムを宣言。コンストラクターへの依存注入までコンパイル時に結び付けるため、実行時のサービス探索は不要です。

01 / DECLARE
using tsr_di;

namespace Sample;

public interface IMessageWriter
{
    void Write(string message);
}

[ServiceClass(Lifetime = Lifetime.Singleton)]
public sealed class ConsoleMessageWriter : IMessageWriter
{
    public void Write(string message)
        => Console.WriteLine(message);
}

[ServiceResolver]
public static partial class AppServices;

メソッドも、型安全に解決

メソッドに属性を付けるだけで、専用の delegate 型を自動生成。Resolve<T>() で操作そのものを取得でき、利用側に実装クラスや専用インターフェースを公開する必要はありません。

02 / FUNCTION SERVICE
public static class TextOperations
{
    [ServiceFunction(ServiceName = "NormalizeText")]
    public static string Normalize(string value)
        => value.Trim();
}

// In a project with AppServices declared:
// using Sample.AutoDefined;
NormalizeText normalize =
    AppServices.Resolve<NormalizeText>();

var result = normalize("  Hello  ");
登録 delegate には、先頭引数を固定する Bind 拡張メソッドも生成されます。

F# / C# INTEROP

F# の関数も、同じ仕組みで。

F# のモジュール関数は .NET の static メソッドとして公開されます。ServiceFunction 属性を付ければ、C# 側では生成された delegate を通して、関数そのものをサービスとして解決できます。

構成：F# のクラスライブラリから tsr-di.Attribute を参照し、C# アプリからその F# プロジェクトを参照します。C# 側では tsr-di と共通の tsr-di.Attribute を直接参照してください。

F# 側の実装をラッパークラスや専用インターフェースで包まず、利用側は NormalizeFromFSharp という操作の契約に依存できます。以下は別々のプロジェクトに置く例です。

F# / Domain.fs
namespace Domain

open tsr_di

module TextOperations =
    [<ServiceFunction(ServiceName = "NormalizeFromFSharp")>]
    let normalize (value: string) : string =
        value.Trim()
C# / Example.cs
using tsr_di;
using Sample.AutoDefined;

namespace Sample;

[ServiceResolver]
public static partial class AppServices;

public static class Example
{
    public static string Run()
    {
        NormalizeFromFSharp normalize =
            AppServices.Resolve<NormalizeFromFSharp>();

        return normalize("  Hello from F#  ");
    }
}

03 / CONTROL

共有する範囲も、明示する。

Scoped は、1 回の Resolve / ResolveAll 内で共有。複数のルートを一度に解決すれば、同じスコープを利用できます。

SHARED SCOPE
var (reader, writer) =
    AppServices.Resolve<IReader, IWriter>();

Transient

要求ごとに新しく生成。既定のライフタイム。

Scoped

1 回の解決呼び出し内でインスタンスを共有。

Singleton

リゾルバー全体でインスタンスを共有。

ServiceKey

名前付きサービスを生成 enum で指定。登録名の不整合はビルド時に検出します。

ResolveAll<T>()

複数の登録をまとめて解決。コンストラクターへのコレクション注入も利用できます。

Services

生成された静的プロパティから直接解決。名前空間に沿った階層をたどれます。
